# NYC Yellow Taxi Trips Bronze Data Product

## Product Summary

This data product contains raw NYC Yellow Taxi trip records for August 2025. It is produced by a streaming-style ingestion pipeline that reads the official TLC Parquet source, publishes micro-batches through a Redpanda/Kafka queue, and writes the consumed records into a bronze JSONL dataset.

The product is useful for trip volume analysis, fare and distance profiling, pickup/dropoff zone exploration, payment type analysis, and as an input for downstream silver/gold transformations.

## Problem Solved

Students or analysts can use this product without rebuilding the ingestion logic from scratch. The dataset is already collected from the public TLC source, split into readable JSONL files, and accompanied by a contract and quality metrics that explain what is inside and how reliable it is.

## Source and Pipeline

- Source: NYC Taxi & Limousine Commission Trip Record Data
- Source page: https://www.nyc.gov/site/tlc/about/tlc-trip-record-data.page
- Current partition: Yellow Taxi, 2025-08
- Orchestrator: Prefect
- Queue: Redpanda, Kafka-compatible topic `nyc_taxi_bronze_ingest`
- Output: `data/streaming/bronze/yellow/2025-08/*.jsonl`

Pipeline flow:

```text
TLC Parquet source -> Prefect-triggered producer -> Redpanda/Kafka queue -> bronze consumer -> JSONL bronze files
```

## How to Access

Clone the repository, start Redpanda, install dependencies, and run:

```powershell
docker compose up -d
python -m venv .venv
. .venv/Scripts/activate
pip install -r requirements.txt
python scripts/run_streaming_pipeline.py --months 2025-08 --chunk-size 5000
```

The current successful run wrote `3,574,091` records as `3,575` consumed queue messages.

## Schema Overview

Important columns:

- `tpep_pickup_datetime`: pickup timestamp
- `tpep_dropoff_datetime`: dropoff timestamp
- `passenger_count`: reported passenger count
- `trip_distance`: trip distance in miles
- `PULocationID`: pickup taxi zone ID
- `DOLocationID`: dropoff taxi zone ID
- `payment_type`: payment method code
- `fare_amount`: metered fare amount
- `tip_amount`: tip amount
- `total_amount`: total charged amount

The full schema is documented in `data_product_contract.yaml`.

## Quality Metrics

The quality report is generated by:

```powershell
python scripts/calculate_data_quality.py --write
```

Required metrics included:

- Row count: number of bronze records after the pipeline run.
- Completeness of key columns: non-null rate for core analytical fields.
- Validity of amount and distance values: percentage of rows with non-negative `trip_distance`, `fare_amount`, and `total_amount`.
- Validity of taxi zone IDs: percentage of rows with pickup and dropoff zone IDs in the TLC taxi zone range.
- Pickup month consistency: percentage of rows whose pickup timestamp belongs to August 2025.
- Freshness: timestamp of the latest updated bronze batch file.

- Completeness of key columns: `100.0%`, threshold `>= 99%`, status `pass`.

- Pickup month consistency: `100.0%`, threshold `>= 99%`, status `pass`.

## Known Limitations

- This is a bronze product, so values are close to the raw TLC source and are not fully cleaned.
- The current submitted partition is `yellow` / `2025-08`.
- Data files are stored locally under `data/` and are ignored by Git because of size.
- Some negative amount or distance values may appear in TLC data due to corrections or unusual operational cases.
- The queue is local Redpanda for coursework, not production Kafka.

## Example Usage

```python
import duckdb

con = duckdb.connect()
df = con.execute("""
    SELECT
        payment_type,
        COUNT(*) AS trips,
        AVG(total_amount) AS avg_total_amount
    FROM read_json_auto('data/streaming/bronze/yellow/2025-08/*.jsonl')
    GROUP BY payment_type
    ORDER BY trips DESC
""").fetchdf()

print(df)
```
